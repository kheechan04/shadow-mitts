# 🥊 Shadow Mitts

**웹캠 하나로 하는 복싱 미트 트레이닝 게임.**
트레이너가 대 주는 미트를 향해, 번호로 불리는 실제 복싱 콤보(1 잽 · 2 크로스 · 3 리드 훅 …)를 쳐서 맞히는 브라우저 게임이에요.
키보드도, 센서도 없이 **웹캠 영상의 포즈 인식만으로** 어느 손으로 · 어떤 펀치를 · 언제 쳤는지 판정해요.

> 영상은 브라우저 안에서만 처리되고 어디로도 전송되지 않아요. 서버가 없는 정적 웹앱이에요.

**▶ 플레이: [shadow-mitts.vercel.app](https://shadow-mitts.vercel.app)** (Chrome·Edge 권장, 웹캠 필요) · 설치형 웹앱(PWA)으로 바탕화면에 설치할 수 있어요.

**이런 점이 달라요**
- 🥊 **실제 복싱 번호 콤보** — "1-2-3"처럼 트레이너가 부르는 번호대로, 키보드·센서 없이 웹캠 하나로 쳐요
- 😆 **내 얼굴이 판정에 반응** — 사진 한 장으로 PERFECT엔 웃고 MISS엔 시무룩한 내 얼굴 (브라우저 안에서만 처리)
- 🎯 **약점 집중 연습** — 자주 틀리는 펀치를 기억해 다음 판에 더 자주 내요
- 🔒 **설치 없이, 영상은 밖으로 안 나감** — 링크만 열면 되고, 앱처럼 설치(PWA)도 돼요

## 특징

- **실제 복싱 번호 콤보** — 1\~6번(잽·크로스·리드/리어 훅·리드/리어 어퍼컷)을 "1-2-3"처럼 출제. 오소독스/사우스포 지원.
- **펀치 종류를 팔 자세로 판단** — 팔뚝 각도·팔꿈치 높이·딥 동작으로 직선/훅/어퍼컷을 구분. 주먹 높이를 맞출 필요가 없음.
- **미트 대 주기 판정** — 미트가 도착해 잠깐 머무는 동안 치면 맞음(도착 무렵은 PERFECT). 한 순간에 맞혀야 하는 리듬게임식이 아님.
- **1인칭 3D 링** — three.js로 모델링한 포커스 미트·글러브·링. 펀치 종류마다 미트가 날아오는 경로와 각도가 달라 한눈에 구분됨.
- **가드 채점** — 치지 않는 손이 턱 근처에 있으면 가드 보너스.
- **지연 자동 보정** — 카메라·인식 지연을 8번의 잽으로 측정해 판정에 반영.
- **리액션 얼굴** — 사진 한 장을 얼굴 좌표로 변형해 PERFECT/MISS 등 표정 5개를 만들고, 판정마다 내 얼굴이 반응. 전부 브라우저 안에서 처리([개인정보 검토](docs/FACE-PRIVACY.md)).
- **약점 적응형 출제** — 펀치별 정확도의 이동평균으로 약한 펀치를 더 자주 출제. 로컬 기록·최고 점수·결과 카드 PNG.
- **카메라 없이 테스트 가능** — 인식 로직은 순수 TypeScript. 합성 데이터 단위 테스트 + 녹화 데이터 재생·채점.

## 풀어낸 문제들

플레이 테스트에서 나온 불편을 **데이터로 원인을 찾아** 고친 과정이에요. 자세한 근거는 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)의 결정 기록에 있어요.

| 증상 | 원인 (측정으로 확인) | 해결 |
|---|---|---|
| 연습 녹화에선 잘 잡히는데 게임에선 훅·어퍼컷을 놓침 | 웹캠이 어두운 방에서 15fps로 떨어짐(프레임 간격 67ms) → 속도가 낮게 측정 | fps에 따라 속도 기준을 자동 조정. 60fps 녹화를 15fps로 솎아 재생: 100 → 154/175 |
| 화면이 뚝뚝 끊김 | 포즈 추론이 메인 스레드를 약 80% 점유(37ms × 초당 22회) | 추론을 Web Worker로 분리 → 화면 27 → 60fps. 같은 이미지로 좌표 동일성 검증 |
| 친 미트가 "잔상"처럼 다시 보임 | 판정 후 지운 3D 모델을 렌더 루프가 다시 생성 | 가상 시간으로 프레임마다 미트 위치를 기록하는 검사로 발견·수정 |
| 기본값을 고쳐도 게임에 반영 안 됨 | 브라우저에 예전 설정이 통째로 저장됨 | 게임 기록을 예전 설정으로 재생해 실제 판정과 34/34 일치 확인 → 바꾼 값만 저장 |
| 크게 친 훅이 어퍼컷으로 분류 | 게임에선 치기 전 손이 살짝 내려가는 "딥"이 생김 | 게임 기록 4판(116펀치)을 정답 라벨로 써서 규칙 보정, 판 단위 교차 검증 |

## 빠른 시작

**바로 하기:** [shadow-mitts.vercel.app](https://shadow-mitts.vercel.app) 을 Chrome·Edge로 열기 (웹캠 필요, 설치 없이 바로)

1. **카메라 켜기** → 처음 방문하면 체크리스트가 안내해요. 1.5\~2m 뒤에서 **머리부터 허리까지** 화면에 보이게 서기
2. 스탠스(오소독스/사우스포)와 난이도 선택 · (선택) 😆 리액션 얼굴 찍기
3. 처음 한 번 **자동 보정** (링에 맞춰 잽 8번)
4. **▶ 한 판 붙자!**

**직접 실행(개발용):**

```bash
npm install
npm run dev          # → http://localhost:5173  (Chrome 권장)
```

자세한 사용법은 [docs/USAGE.md](docs/USAGE.md).

> Windows PowerShell에서 `npm` 실행이 막히면 `npm.cmd run dev`를 쓰면 돼요.

## 명령어

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm test` | 단위 테스트 (카메라 불필요) |
| `npm run eval` | `recordings/*.json` 녹화로 펀치 인식 채점 (`-v` 이벤트 목록, `--mirror` 좌우 반전 검사) |
| `npm run fps-check` | 녹화를 30/20/15/12fps로 솎아 채점 (느린 카메라 대비) |
| `npm run game-report -- <파일>` | 게임 기록(결과 화면 "이번 판 기록 저장")을 재생·재판정 |
| `npm run build` | 정적 빌드 → `dist/` |

## 기술 스택

- **포즈 인식**: MediaPipe Pose Landmarker (`@mediapipe/tasks-vision`, lite 모델), **Web Worker에서 CPU 추론**(GPU는 옵션)
  — 왜 YOLO가 아니라 MediaPipe인지: [docs/MODEL-CHOICE.md](docs/MODEL-CHOICE.md)
- **얼굴**: MediaPipe Face Landmarker 좌표 + Delaunay 메시 워프(WebGL) — 생성형 AI 없음
- **배포**: Vercel(정적 호스팅, push 시 자동 배포) + PWA(서비스 워커로 게임·모델 파일 캐시, 오프라인 실행)
- **3D**: three.js (절차적 모델링, 그림자, ACES 톤매핑)
- **언어/빌드**: TypeScript, Vite, 프레임워크 없음
- **테스트**: Vitest (Node)
- **사운드**: WebAudio 합성 (오디오 파일 없음)

## 구조 한눈에

```
src/core/   순수 로직 (DOM·카메라 없음, Node에서 테스트)
  features.ts   랜드마크 → 팔 특징 (어깨 중점 기준, 몸통 길이 단위)
  punch.ts      팔별 상태기계로 펀치 검출
  classify.ts   팔 자세로 직선/훅/어퍼컷 분류
  game.ts       출제·판정·점수·콤보·지연 보정
  params.ts     모든 튜닝 임계값 (화면 슬라이더로 노출)
  progress.ts   약점 적응형 출제·약점 리포트
src/app/    브라우저 (카메라, MediaPipe, three.js 장면, UI, 기록·결과 카드·PWA)
src/face/   리액션 얼굴 (얼굴 좌표 → 사진 변형, face.html 실험실)
tests/      합성 포즈 단위 테스트 + 녹화 회귀 테스트
```

설계 원칙, 인식 방식의 근거, 테스트·튜닝 방법은 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
최초 기획서는 [DESIGN.md](DESIGN.md).

## 인식 성능 (측정값)

사우스포 1인의 웹캠 녹화 19개(175펀치, 12\~58fps)로 측정. 좌우 반전(오소독스)으로 돌려도 같은 결과.

| 지표 | 결과 |
|---|---|
| 가드만 / 몸통 회전만 한 구간의 오검출 | 0 |
| 친 손 + 시점 검출 | 165/175 (94%) |
| 펀치 번호까지 정답 | 160/175 (91%) |
| 같은 녹화를 15fps로 솎았을 때 (어두운 방의 웹캠) | 154/175 (88%) |
| 작게 친 어퍼컷 (13\~15fps) | 리드 8/10 · 리어 8/10 |
| 추가 검출 (반대손·중복) | 12회 |

**한계** — 한 사람·한 공간·한 카메라로 만든 규칙이에요. 웹캠 1대는 앞뒤 깊이를 거의 못 보므로
카메라 정면으로 뻗는 펀치는 화면상 움직임이 작고, 저프레임(25fps)에서 아주 빠른 연속 잽을 놓칠 수 있어요.
다른 사람·환경에서는 개발자 도구(⚙)의 슬라이더 조정이 필요할 수 있어요.
