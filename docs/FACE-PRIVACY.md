# 리액션 얼굴 기능 — 개인정보·약관 검토 (시제품 기준)

작성: 2026-09-24. 법률 자문이 아니라 개발 중 확인한 사실과 근거를 정리한 문서다.
정식 서비스(특히 상업적 운영) 전에는 전문가 검토를 받는 것을 권장한다.

## 1. 기능이 실제로 하는 일 (구현 기준)

| 단계 | 처리 위치 | 비고 |
|---|---|---|
| 웹캠 촬영 (버튼 → 3초 카운트다운 → 1장) | 브라우저 | 찍자마자 카메라 트랙 정지. **파일 업로드 기능 없음**(본인 얼굴만) |
| 얼굴 위치 좌표 478개 추출 (MediaPipe FaceLandmarker) | 브라우저 (WASM) | 표정 수치(blendshapes) 출력 **끔**, 얼굴 인식·신원 확인 **안 함** |
| 사진 변형 + 만화 효과로 표정 5개 | 브라우저 (WebGL/Canvas) | 생성형 AI 아님 — 사용자 사진의 픽셀만 이동 |
| 보관 | 페이지 메모리(변수·캔버스)만 | 사진·좌표는 localStorage·IndexedDB·서버 어디에도 저장 **안 함**. "지우기"·창 닫기로 폐기. (게임에서 고른 **카메라 장치 번호**만 읽어 옴 — 얼굴과 무관) |

**네트워크 검증** (헤드리스 Chrome, 촬영\~표정 생성\~지우기 전 과정의 모든 요청 기록):
- 외부 요청은 전부 GET: `fonts.googleapis.com`/`fonts.gstatic.com`(글꼴), `cdn.jsdelivr.net`(MediaPipe WASM), `storage.googleapis.com`(얼굴 모델 파일)
- POST 등 본문이 있는 요청 **0건** → 사진·좌표는 전송되지 않는다
- 위 요청들로 IP 주소·브라우저 정보는 해당 CDN에 전달된다(일반 웹사이트와 동일). 페이지 안내문에 명시했다.

### 게임에 붙인 뒤 (메뉴 "😆 리액션 얼굴")
- 게임이 이미 켜 둔 카메라 화면에서 **한 프레임만** 가져와 같은 처리(`src/face/reactions.ts`)를 한다. 게임용 카메라는 게임 동안 켜져 있다(원래 동작).
- 가져온 프레임과 얼굴 크롭은 표정을 만든 직후 비우고(`wipe`), 남는 건 표정 이미지 5장뿐이다. 메뉴의 "지우기"·창 닫기(`pagehide`)로 폐기한다.
- 결과 카드 PNG에는 **"카드에 내 얼굴" 스위치가 켜져 있고 사용자가 저장 버튼을 누를 때만** 얼굴이 들어가며, 내 기기에 내려받는 파일일 뿐 업로드하지 않는다.
- 로컬 기록(`shadowmitts.progress.v1`)에는 점수·콤보·정확도·펀치별 명중 수만 저장한다(얼굴·영상·관절 좌표 없음).
- 표정 이미지는 리액션 창·결과 화면에만 그린다. "이번 판 기록 저장"(분석용 파일)에는 **들어가지 않는다**(관절 좌표·판정만).
- 헤드리스 검증: 카메라 켜기 → 얼굴 찍기 → 게임 → 결과까지 전체 요청이 GET뿐이고, 본문 있는 요청은 0건이다.
- 안내 문구(메뉴): "🔒 사진은 이 기기 밖으로 안 나가고, 저장하지 않아요" / 찍은 뒤 "이 기기 밖으로 안 나가고, 창을 닫으면 사라져요".

### 배포(Vercel)와 PWA
- 호스팅은 정적 파일만 내려준다(서버 코드 없음). 접속 기록(IP 등)은 일반 웹 호스팅과 같다. **Vercel 방문 분석(Analytics)은 켜지 않는다** — 켜면 안내 문구를 고칠 것.
- 서비스 워커(`public/sw.js`)가 저장하는 것: 게임 빌드 파일, 글꼴, 버전 고정된 MediaPipe WASM·모델. 헤드리스로 캐시 목록을 확인해 사진·영상·좌표가 없음을 검증했다.
  카메라 프레임·포즈·얼굴은 fetch를 거치지 않으므로 캐시에 들어갈 수 없다.

## 2. 법령·가이드라인 검토 (대한민국 개인정보 보호법 기준)

- **얼굴 사진 자체**는 개인정보지만, 그 자체로 **민감정보는 아니다**. 민감정보(시행령 제18조 제3호)는
  "개인의 신체적, 생리적, 행동적 특징에 관한 정보로서 **특정 개인을 알아볼 목적으로** 일정한 기술적 수단을 통해 생성한 정보"다.
  이 기능은 누구인지 알아보는(인증·식별) 처리를 하지 않으므로 민감정보 처리에 해당하지 않는다.
- 개인정보보호위원회 「생체정보 보호 안내서」(2024.12)는 생체정보를 "특정 개인을 인증·식별하거나 **개인에 관한 특징을 알아보기 위해**
  일정한 기술적 수단을 통해 처리되는 정보"로 넓게 정의한다. 그래서 표정·감정 분석(blendshapes)은 쓰지 않도록 설계했다
  (얼굴 좌표는 사진을 늘리고 당기는 데만 쓴다).
- **운영자는 사진을 수집하지 않는다**: 사진과 좌표가 사용자 기기 밖으로 나가지 않으므로 운영자가 개인정보를 받거나 보관하지 않는다.
  그래서 동의서·보관 기간·파기 절차 같은 "수집" 전제 의무가 생기지 않는 구조로 본다(단, 법적 판단은 전문가 확인 권장).
  같은 이유로 만 14세 미만 법정대리인 동의(수집 시 요건)도 해당하지 않는 구조다.
- 그래도 투명성 차원에서 촬영 전 안내문(무엇을, 어디서, 얼마나 보관)을 항상 표시한다.

## 3. 사용 기술의 약관·라이선스

- `@mediapipe/tasks-vision`: **Apache-2.0** (설치된 package.json 확인)
- Face Landmarker 모델(Face Mesh V2) 모델 카드: **Apache License 2.0**. 주 용도는 "AR 엔터테인먼트".
  범위 밖: 생명과 직결된 결정. "예측된 얼굴 좌표는 **얼굴 인식이나 신원 확인을 제공하지 않고**, 고유한 얼굴 표현을 저장하지 않는다" —
  이 기능의 사용 방식(재미용 표정 변형)과 맞는다.
- 모델은 버전 고정 URL(`float16/1`)로 불러온다.

## 4. 악용 방지

- 업로드 없이 **실시간 웹캠 촬영만** 허용해서, 타인의 사진을 가져와 표정을 조작하는 용도로 쓰기 어렵게 했다
  (개발 모드 전용 테스트 훅 `__faceLabTest`는 프로덕션 빌드에서 제거된다).
- 얼굴 실험실(face.html)의 결과물에는 저장·공유 기능이 없다. 게임의 결과 카드는 사용자가 직접 내려받는 방식만 쓴다(위 "게임에 붙인 뒤").

## 5. 안내문이 사실과 일치하는지 (face.html)

| 안내 문구 | 근거 |
|---|---|
| 이 기기 밖으로 나가지 않아요 / 서버로 보내지 않아요 | 서버 없음, 네트워크 기록에 전송 0건 |
| 저장하지 않아요, 지우기·창 닫기로 사라져요 | 메모리에만 보관, 사진·좌표에는 저장소 API 미사용(카메라 선택값만 읽음), `pagehide`·지우기에서 캔버스·변수 폐기 |
| 찍자마자 카메라는 꺼져요, 업로드는 받지 않아요 | `stopCamera()`를 촬영 직후 호출, 파일 입력 없음 |
| 표정 분석·얼굴 인식을 하지 않아요 | `outputFaceBlendshapes: false`, 좌표는 변형에만 사용 |
| 글꼴·모델 파일을 받을 때 IP 주소가 전달돼요 | 위 GET 요청 목록 |

코드를 바꿀 때 이 표가 계속 참인지 확인할 것. 참이 아니게 되면 안내문을 먼저 고친다.
